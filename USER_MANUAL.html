Current User Manual

This manual describes the current application only. Historical revision notes are intentionally not bundled in the deployment ZIP.

Understand the guided build editor

Prototype → open a build → BUILD WORKFLOW strip at the top.

The BUILD WORKFLOW strip is the guided editor/navigation. Green = completed, yellow = current required action, grey = future, red = blocked. Click the tile by title; its detailed editor opens below the fixed build summary. E0/E1/V/P assurance profiles show different required steps, so step numbers are not universal.

Plan a prototype build

  1. Open Prototype → [build] → Material source & feasibility and confirm the exact BOM source/arrival/lot evidence.
  2. Open Route / method definition and confirm released processes/tests or controlled development.
  3. Open Resource plan & committed timing. Build the schedule manually or choose PREVIEW AUTO-PLAN. AUTO-PLAN is optional.
  4. LabOS plans around accepted lab closures, vacations, maintenance, calibration/training windows and existing bookings. Those are operating constraints, not items you must remove.
  5. If a true readiness gap exists, use the named action for the exact resource; for example, open the exact equipment evidence rather than a generic planning resolution.
  6. When every required planning task has one valid booking, COMMIT CURRENT PLAN becomes available immediately. You can commit a deliberately non-optimal manual plan without running AUTO-PLAN first.

Control Plan / special approvals

Prototype → [build] → BUILD WORKFLOW → tile titled “Reuse approved controls…” / “Control Plan & special approvals”.

This tile appears only when the assurance profile requires the control step. Open the tile. If a compatible approved Control Plan is available you can link it. Otherwise choose Create & define Control Plan; LabOS opens the build-specific Control Plan editor immediately. Link characteristics to route steps and define limits/specification, method/gauge, objective evidence and reaction plan. Required independent approval is performed from the fixed SIGN-OFF area in the build header.

Build readiness

Prototype → [build] → BUILD WORKFLOW → Build readiness.

Open the remaining readiness item. It should name the exact equipment, capability, skill or evidence and provide a direct next action. Accepted planning situations such as a closure or vacation must be planned around, not removed to make readiness green.

Execute / verify / release

  1. Build samples & capture process evidence: create the sample register, execute each route step and record required process/Control Plan evidence.
  2. Characterise, evaluate & disposition exceptions: record requested results; investigate and disposition any quality hold.
  3. Formal release approval: complete the required release sign-off.
  4. Deliver, retain records & feed learning: acknowledge delivery, retain records/lessons and close.

Sister-lab transfer

Planning → Lab Network Recovery or the sister-lab action from a build/task plan.

  1. Sending lab compares feasible sister labs and submits a formal transfer request with rationale.
  2. Switch Active lab to the receiving lab.
  3. Open My Work or Planning → Lab Network Recovery → Transfer requests & acceptance.
  4. The receiving Lab Planner/Lab Manager accepts or rejects with rationale. Acceptance reruns the canonical planner before LIVE routing changes.

Audit Readiness

Governance → Audit Readiness.

  1. Select the relevant IATF 16949 or ISO/IEC 17025 framework view.
  2. Review Internal audit section overview. Each row states the assessment, score and objective LabOS evidence used.
  3. Review the Relevant norm map. A Manual review row means no automated evidence rule is mapped; it is deliberately not shown as compliant.
  4. Prioritise Major findings, then Minor findings. Recommendations / opportunities for improvement are preventive and are not nonconformities.
  5. Use the Prototype build turtle to review inputs, resources, people, controls, outputs and measures around the app process flow.
  6. Choose Audit evidence pack → Print / save PDF for the printable evidence set.

The readiness percentage is a system-assisted internal indicator, not a certification score. Ready = 100%, Minor = 50%, Major = 0% at check level; risk weights are used for the overall readiness calculation. Unmapped norm sections remain manual review items.

Task replan history

Prototype → [build] → Resource plan & committed timing → Task replan history.

Each row shows the movement, task, From → To date, reason category and retained free-text rationale. This is separate from customer commitment history.

Resource Assurance

Resource Assurance in the left navigation.

Use Calibration, Maintenance and Training filters to locate the exact resource. Schedule upcoming readiness work and retain the certificate/service/qualification evidence. A valid calibration interval should not trigger unnecessary recalibration; missing approval/evidence should guide to the evidence record instead.

Reports

Open Reports or the build closeout step. Build Reports and the Audit Evidence Pack use the browser print dialog; choose Save as PDF when a portable copy is required.

Prototype route/method hand-off

Prototype → open build → Build Workflow → Reuse released route / work instructions

  1. If a method is incomplete, the fixed Next Step action names that exact operation and opens the correct correction path.
  2. Operations such as Surface Preparation that are intentionally manual/no-dedicated-equipment are not blocked for lacking a machine.
  3. If the current user is the Lab Planner, choose Switch to Process Engineer · …. The same build remains open and the exact Process Engineering action is shown immediately.
  4. After route/method confirmation, the workflow proceeds forward to Controls and then Planning; it should not bounce back unless the controlled definition actually changes.

Laboratory scope & resource evidence

Lab Standards & Resources → Equipment & laboratory scope

The scope register lists every registered equipment asset and links capability/range/resolution with current readiness, calibration certificate/validity, maintenance due/history and the certified skills/people associated with released methods using that capability.

Build Report capability plots

Reports → open Build Report → SC / CC & classified characteristics

Capability/statistical detail is expanded by default. Numeric special/critical characteristics show the measured distribution, specification/target/mean markers, Cpk context where supported by the data, normality result, anomalies and coverage.
