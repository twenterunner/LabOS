REV 1.0.108 · ANDROID / COMPACT SCREENS

Switching demo roles on mobile

On Android, tablets and compact browser windows, tap the hamburger menu. The Demo role selector is now shown at the top of the navigation drawer. Choose the required role; LabOS saves the selection, refreshes the role-based navigation and dashboard, and closes the drawer automatically.

The role selector is deliberately kept out of the crowded compact top bar. On full desktop widths the original header role selector remains available. Both selectors stay synchronized.

REV 1.0.108 · SCENARIO INPUTS

Only ask for assumptions that change the simulation

Current risk / recovery scan uses the current LIVE portfolio and therefore asks for no dates or resource. Priority escalation also needs no dates. Material delay asks only when material will be available. Equipment outage and person absence ask for the affected resource plus an unavailable date range; lab closure asks only for the unavailable date range.

Hidden fields are not stored as scenario assumptions. This prevents inactive default dates from appearing to constrain a recovery scan.

REV 1.0.108 · SCENARIO LAB STAGE 2

Optimization & recovery on an operational twin

Open Planning → Scenario Lab. Select a target build and optionally simulate an equipment outage, person absence, lab closure, priority escalation or material delay. The scenario is clearly marked NOT LIVE; it runs on a disposable copy of the current operational state.

The scenario baseline is the current accepted plan with the selected scenario assumption applied, before optimization. Generate & rank better options runs the same canonical constrained-planning engine as LIVE planning and tests protected resequencing, alternative people/equipment, controlled readiness/training, target-first escalation, portfolio trade-offs, weekend capacity, complete sister-lab routing, external facilities and governed split-route concepts.

LabOS now suppresses any alternative that does not improve the baseline for the selected objective. Results with an unresolved target or residual scenario conflicts are not proposed. The comparison table shows the baseline beside every surviving option with target finish/status, network OTD, total portfolio late days, remaining conflicts, worsened projects, moved bookings, added cost and a concise improvement-vs-baseline explanation.

If no option beats the baseline, LabOS explicitly says to keep the baseline instead of manufacturing a recommendation. If the baseline contains a structural scenario conflict and no verified recovery is better, change the assumptions or resolve the blocker.

Use Review impact before applying. Apply to LIVE requires a rationale, creates audit evidence, rejects non-improving options and retains one-click undo. A split-route result remains a review proposal only; transport/custody/handover feasibility must be governed before mixed-site execution is planned.

Use Save analysis to retain the compact scenario definition and result summary. Running it again solves against the latest LIVE state rather than reusing stale candidate schedules.

REV 1.0.108 · AUTO PLAN DECISION LOGIC

Feasible does not automatically mean better

When AUTO PLAN runs, the current accepted LIVE plan is the baseline. A result is shown under Verified optimization options only when it is no worse than baseline for unplanned builds, total days late, maximum project delay, commitment worsening and priority-weighted lateness, and at least one outcome improves.

The comparison table places the LIVE baseline beside every verified optimization before you choose. A plan that schedules more previously-unplanned work but creates additional lateness is not called an optimization. If it is complete and potentially useful for blocker recovery, it appears separately under Recovery trade-offs — not optimization proposals, with a clear What improves / What gets worse summary. Such an option can be reviewed deliberately but is never marked Recommended.

If one recovery result is equal or worse than another recovery result on all compared KPIs, LabOS suppresses the inferior result. If no tested strategy safely beats the baseline, AUTO PLAN explicitly tells you to keep the current baseline. Partial candidates that still contain blockers remain in the guided recovery workflow instead of being presented as plans to accept.

REV 1.0.102 · PLANNING & LAB NETWORK

Day-level planning and unambiguous network routing

Planning timelines now show day-level resolution. Swipe left/right on touch devices or click-drag the chart with a mouse to move the visible date window; use −, Fit and + to change zoom. Exact working-hour timestamps remain internal so equipment, people, readiness and dependency conflicts are still validated.

Lab Network Recovery contains only active builds that have no canonical plan, an incomplete/unresolved canonical plan, or a complete plan that finishes late. A stale forecast field is never shown as a reliable finish when plan coverage is incomplete.

Compare sister labs distinguishes the current accepted plan finish from a fresh replan from now. A current reserved plan may therefore finish earlier than a new replan against today’s remaining capacity. Any active project can also be routed electively to a sister lab; Recovery and Elective moves are tracked separately in management KPI.

REV 1.0.100 · LAB NETWORK

Independent laboratories, one planning engine

Use the Active lab selector to work inside one laboratory. People, equipment, material stock, closures/readiness events and operational planning are owned by that lab. Products carry separate default sites for Prototype, Validation / Testing and Failure Analysis; new requests route to the corresponding default while existing controlled builds never move silently.

When home-lab timing is late or unresolved, open Planning → Lab Network Recovery → Compare sister labs. LabOS runs the same canonical planner independently at each internal site, shows the real forecast and requested-date result, and compares those alternatives with the configured external-facility cost/lead-time benchmark. A sister-site result becomes live only after Review transfer, rationale and acceptance. The original home site remains traceable. Network KPIs then report sister-lab builds, internal hours retained and estimated outsourcing spend avoided.

Administrators configure sites and product defaults in Laboratory network & product routing. Stable site IDs are intentionally suitable for later ERP/PLM/API/SSO/SCIM integration.

REV 1.0.100 · PLANNING

One engine, one timeline, one deadline definition

AUTO PLAN, MANUAL PLAN and Escalation share the same controlled scheduling engine and canonical build-task definition. In every planning swimlane use − · Fit · + for zoom and swipe/click-drag horizontally to move the visible date window earlier or later. The red Required delivery marker and planning-health status use the same 17:00 requested-date cutoff and the exact final canonical booking end, so a bar cannot visually cross the deadline while still being classified on time. There is no separate Horizon field. Month, ISO calendar week/year and day/date headers stay aligned in the Master Planner, build-specific planning step and sticky build cockpit. The six planning-health tiles filter the lanes themselves. An active build without a valid schedule remains visible as Schedule unresolved, and blocked planning opens guided recovery before the same solver recalculates.

REV 1.0.90 · INFORMATION ARCHITECTURE & VISUAL CONSISTENCY

Each area has one clear owner

LabOS now separates controlled definitions, operational assurance, planning scenarios, configuration and management reporting more explicitly. Lab Standards & Resources owns equipment master/scope, released methods/tests, competencies, people and workplace standards. Resource Assurance owns the live calibration, maintenance, training and EHS schedule. Lab Performance owns the potential-project pipeline and its probability-weighted KPI/capacity view. Planning may visualise that demand in planning scenarios but does not maintain a duplicate project register. Configuration owns organisation/requesting teams, customers, costing, lab setup and system data.

Typography, table density, buttons, status pills, section navigation and card spacing use one cross-tab visual system. Long report/table text wraps by words rather than splitting characters, and small uppercase labels use reduced tracking for better readability.

REV 1.0.60 · GUIDED RESOLUTION

Resolve means complete the exact missing evidence

For engineering clarifications, the Action Centre shows the blocker cause, current owner, next owner and the exact missing field directly in the Resolve modal. Interface blockers require a specific programming/calibration interface definition. Save the definition, then run the guided feasibility reassessment; LabOS opens the next real material, process/method or planning step and never silently commits a date.

REV 1.0.59 · GAGE R&R

System recommendation, human decision

Quality → MSA / Gage R&R shows a conservative automotive recommendation separately from the authorised reviewer decision. The default guide uses a balanced crossed study, typically 10 parts, 2–3 operators and 2–3 repeated trials, <10% as acceptable, 10–30% as application-dependent, >30% as unacceptable, and ndc ≥5. IATF 16949 does not create one universal numeric acceptance table; customer-specific requirements and intended-use risk take precedence. Any decision that overrides the LabOS recommendation requires retained rationale.

REV 1.0.59 · KPI / AUDIT

5S trend and exact readiness resolution

Management → Lab Performance includes a 5S pillar and trend based on recorded workplace checks. Audit Readiness calibration blockers show the remaining evidence chain explicitly: schedule the activity, record the certificate, complete the required certificate review, then recheck. Scheduling alone never clears readiness.

REV 1.0.59 · SIGN-OFFS

One decision package, explicit signers

LabOS consolidates repeated approval records owned by the same signer at the same decision point. The package shows each required person/role, what the signature covers and signed/pending progress. If several independent roles are required, every signer remains visible and must sign separately. The guided build cockpit and top-level workspaces show the next action and owner so the user does not need to infer who acts next.

REV 1.0.59 · PLATFORM STRUCTURE

Prototype now, Validation and Failure Analysis later

Requests is the shared intake concept. Prototype is the operational workstream in this POC. Validation and Failure Analysis are intentionally visible as future workstreams so all three can share one planning, resources, quality, evidence and traceability backbone instead of becoming separate applications.

For measurement-system assurance, open Quality → MSA / Gage R&R. Existing studies can be uploaded, or a guided crossed/balanced Gage R&R can be run in LabOS. Each study retains its date, evidence and explicit links to the process and/or Standard Test plus gage/equipment.

REV 1.0.91 · GUIDED BUILD WORKFLOW

One sticky command surface

The sticky build header is the only place for the workflow Next Action and formal Sign-off. Sign-off remains grey until minimum prerequisites are met; its compact checklist shows completed prerequisites with green ticks and missing prerequisites with yellow dots. Each workflow page begins with its purpose and a consistent substep checklist. Green means complete/ready, yellow means current/in progress, red means blocker, and grey means future.

Request setup now includes an explicit Control Plan strategy: a compatible approved baseline is linked by default when available, or Engineering can deliberately choose to define/select it later in the Controls workflow. Potential projects remain maintained in Lab Performance / KPI.

CORE UX CONTRACT

No dead ends

An actionable recommendation must either be implemented by LabOS when accepted or lead through a functional guided workflow to resolution, evidence and recalculation. Partial capacity changes and accepted-but-unimplemented improvement proposals are not valid states.

Planning situations

A staff absence, equipment outage or lab closure is simulated together with the resulting portfolio plan. If the complete solution is blocked, the exact blocker opens its competency/equipment/staff resolver. The pending proposal retries automatically after resolution. The constraint and schedule are accepted together or neither is saved.

ROUTE & CONTROL PLAN

Define only what this build needs

The confirmed route fixes the released process revision used for execution. The approved Control Plan adds formal characteristics, method, reaction plan and sampling to the applicable route step.

Method gaps

A real gap opens guided process development. Each completed development action stores real trial/parameter/capability/work-instruction/approval evidence; releasing the method materialises that evidence into the released process.

BUILD EXECUTION

One governed data cockpit per route step

Select execution group → recipe/setup → start operation → process/CP matrix → complete operation.

Large batches

For more than eight samples, sample selection and the Sample Register are collapsed by default. All pending samples remain selected for execution. Open the foldout only to search/change the group. The batch/sample matrix remains the primary data-entry surface.

Control Plan sampling

100% requires every applicable sample. Reduced sampling identifies the required subset. Formal CP measurements and normal process data share the same route-step matrix; duplicate characteristics are not entered twice.

TRACEABILITY

Serial History

Search by working sample number, permanent Lab Sample ID, formal serial, build, product, customer, material lot, process, operator or equipment. Results are grouped in collapsible sections; opening a sample exposes its genealogy and evidence.

QUALITY · MSA / GAGE R&R

Make measurement-system evidence visible where it is used

Use Quality → MSA / Gage R&R to upload an existing controlled MSA study or run a guided Gage R&R. Studies are linked to the applicable process and/or Standard Test, equipment/gage, characteristic, product/configuration and study date. Process, test and equipment detail views show their linked MSA evidence and offer a guided path when none exists.

RESOURCE ASSURANCE

Calibration, maintenance and training

Duration is editable in the scheduling transaction. LabOS checks controlled collisions, automatically replans affected builds where feasible, and refuses to save an unresolved reservation. Reports retain links to calibration, maintenance and training evidence/certificates.

IMPROVEMENT

Accept means implement

The Improvement Scan only surfaces prevalidated staffing/equipment load-balancing proposals that can be applied completely. Acceptance rechecks qualification/readiness/conflicts, changes the actual controlled bookings/route assignments and verifies the result before committing.

Production deployment boundary

This static POC is not a production QMS/LIMS. Enterprise deployment needs authenticated users, server-side permissions, shared transactional storage, validated e-signatures where applicable, immutable audit retention, backups/security validation and governed integrations to corporate systems.

REV 1.0.54 · DAILY UX

Execution, personal actions and workplace control

Build execution: route operations are selected from the sticky route submenu in the build cockpit. Use the single current guided action to start an execution, record only the released-process / approved-Control-Plan data required at that operation, and complete it. CSV and build-specific-field tools are inside the data matrix.

Action Centre: each signed-in user sees only actions assigned to that person. Build readiness and blocking logic still considers all unresolved actions, regardless of who owns them.

5S: configure workplace zones and accountable owners in Lab Standards & Resources. A 5S check scores Sort, Set in order, Shine, Standardize and Sustain; any score below the configured acceptance threshold creates an owner action that can close only with resolution evidence.

Audit scope: laboratory capability scope is controlled by equipment category/capability. Individual equipment remains traceable as a member of that category.

Test families: maintain the controlled family list from the Standard Test Library and assign each test to a family.

5S WORKPLACE CONTROL

Run and resolve 5S checks

Run 5S check now opens the selected zone reliably. Scores below the workplace standard create actions for the accountable owner; the action closes only after guided resolution evidence is recorded.

REV 1.0.54 · LIVE RESOLUTION

Readiness, material limits and mobile data capture

Readiness status is calculated from the current underlying bookings/evidence. After a valid reassignment or other resolution, the affected check is rerun and the workspace changes to Ready immediately. Staff alternatives shown by the planning resolver are prevalidated against the complete plan and an explicitly selected person is retained.

Engineering material receipt defaults to the exact remaining BOM need. Excess remains available buffer stock; a short receipt creates a material-output limiter and prevents creation of samples beyond the currently supportable quantity.

On mobile, dialog width follows the browser visual viewport. Process-data matrices keep sample identity and short CP/measurement labels in the matrix while method, sampling and reaction-plan detail remains in the surrounding summary/foldout.

REV 1.0.54 · HARD GATES

Green means genuinely completed

In Lab Setup and the guided build workflow, future stages remain locked until the current required stage has the minimum controlled information/evidence. A setup step receives a green tick only after it has been deliberately completed; pre-existing or imported data alone never creates a green milestone.

LESSONS & LEARNING

Evidence-based closeout learning

At Engineering handover & close, LabOS derives candidate lessons from the build record: quality/yield exceptions, schedule churn, material constraints, process-time overruns, failed controlled measurements and released method development. Duplicate evidence is consolidated. Every proposal must be accepted or rejected with rationale before closeout. Accepted learning is retained and included in the Build Report.

PLAIN-LANGUAGE REPORTING

Route, material and commitment terminology

11 of 12 operations means that execution evidence has been retained for 11 of the 12 required route operations for that sample. Not linked to current BOM means a historical/migrated material issue remains traceable but does not satisfy a current BOM requirement. In Planning, Commitment decisions identifies builds where the feasible forecast differs from the date currently promised; open the metric to review and decide each change.
