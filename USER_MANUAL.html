Current User Manual

This manual describes the current application only. Historical revision notes are intentionally not bundled in the deployment ZIP.

Understand the guided build editor

Prototype → open a build.

Follow yellow. Green means the controlled evidence for that stage/substep is complete. Exactly one yellow stage and one yellow action identify what must happen now. Grey is future/locked. A later stage cannot become actionable before the earlier controlled requirement is complete.

The sticky cockpit remains visible while you work and is the operational summary for the build: Build number, Requested delivery, Original commitment, Current commitment, Latest forecast, Build workflow, Substeps, Planning, Current stage & owner, Approvals, and Next step & owner.

Every process-step page follows the same order: Purpose → DO THIS NOW → Evidence progression → detailed work. The yellow action is executable, names its owner, and states what “done” means. When the underlying evidence is completed, the step turns green and LabOS moves yellow forward automatically. Approved evidence is not followed by a second mystery acknowledgement.

A-samples use Engineering need → Material → Process & methods → Controls → Plan & commit → Build readiness → Build & evidence → Verify & disposition → Handover & learn. B- and C-samples use the same path plus Formal release before Handover & learn.

The workflow provides IATF/ISO-oriented evidence support, not a certification claim. Controlled revisions, required approvals, competence, measurement-resource status, traceability, nonconformity control and objective evidence remain authoritative.

Plan a prototype build

  1. Open Prototype → [build] → Material source & feasibility and confirm the exact BOM source/arrival/lot evidence.
  2. Open Route / method definition and confirm released processes/tests or controlled development.
  3. Open Resource plan & committed timing. Build the schedule manually or choose PREVIEW AUTO-PLAN. AUTO-PLAN is optional.
  4. LabOS plans around accepted lab closures, vacations, maintenance, calibration/training windows and existing bookings. Those are operating constraints, not items you must remove.
  5. If a true readiness gap exists, use the named action for the exact resource; for example, open the exact equipment evidence rather than a generic planning resolution.
  6. When every required planning task has one valid booking, COMMIT CURRENT PLAN becomes available immediately. You can commit a deliberately non-optimal manual plan without running AUTO-PLAN first.

Control Plan / special approvals

Prototype → [build] → BUILD WORKFLOW → tile titled “Reuse approved controls…” / “Control Plan & special approvals”.

This tile appears only when the assurance profile requires the control step. Open the tile. If a compatible approved Control Plan is available you can link it. Otherwise choose Create & define Control Plan; LabOS opens the build-specific Control Plan editor immediately. Link characteristics to route steps and define limits/specification, method/gauge, objective evidence and reaction plan. Required independent approval is performed from the yellow action bar.

Build readiness

Prototype → [build] → BUILD WORKFLOW → Build readiness.

Open the remaining readiness item. It should name the exact equipment, capability, skill or evidence and provide a direct next action. Accepted planning situations such as a closure or vacation must be planned around, not removed to make readiness green.

Execute / verify / release

  1. Build samples & capture process evidence: if the sample register is incomplete, the required sample count stays visible as the yellow prerequisite. Create the sample records, then use Sample / serial register to populate formal serials individually, generate a serial series, or import/export CSV while the permanent Lab Sample ID remains unchanged.
  2. Use Batch-fill parameters to populate a controlled sample parameter across blank cells or intentionally replace the batch. Use Evidence matrix and the process-step CSV import/export tools for larger parameter/result sets. Batch changes remain audit logged.
  3. Execute each route operation and record required process/Control Plan evidence. The yellow action follows the actual next incomplete operation/evidence requirement.
  4. Characterise, evaluate & disposition exceptions: record requested results; investigate and disposition any quality hold/nonconformity.
  5. Formal release approval: complete the configured release sign-off where required by the assurance profile.
  6. Deliver, retain records & feed learning: acknowledge delivery, retain records/lessons and close.

Sister-lab transfer

Planning → Lab Network Recovery or the sister-lab action from a build/task plan.

  1. The sending lab compares feasible sister labs and opens the candidate it wants to request.
  2. Before sending, review the visible decision facts: sample quantity, proposed start/finish, forecast, planned hours, equipment and assigned people. Expand the operation-plan foldout only when more detail is needed.
  3. Submit the formal transfer request with the sender rationale. No LIVE routing changes yet.
  4. At the receiving lab, open My Work or Planning → Lab Network Recovery → Transfer requests & acceptance. The receiver sees the same proposed sample/timing/resource evidence before deciding.
  5. Accept or reject with receiver rationale. Acceptance reruns the canonical planner against the receiver's current LIVE capacity, closures, people, equipment and readiness before routing changes.

Materials & Inventory corrections / scrap

Materials & Inventory → Edit / scrap… or Prototype → [build] → Material source & feasibility → Material quantity & disposition.

Received lot identity (part number, revision and lot/batch) is immutable. Authorised users may make controlled corrections without rewriting genealogy:

  1. Set / correct available quantity after a physical count.
  2. Add received / found quantity to the same controlled lot.
  3. Scrap / consume available quantity with mandatory reason and optional NCR/scrap-ticket/reference.
  4. Quarantine / release a lot and update location, expiry/retest date, supplier/source or receipt/certificate reference.
  5. For a build, Adjust reservation to increase/reduce/release exact-lot reserved quantity. For already issued material, Scrap / loss creates a separate disposition record and reduces usable issued quantity; it does not overwrite the issued genealogy.

Every adjustment records actor, timestamp, before/after quantity, reason and supporting reference in the transaction/audit history.

Audit Readiness

Governance → Audit Readiness.

Build audit population = completed/CLOSED builds only. Open nonconformities on in-progress builds remain in Operational watch and are not included in the audit score/report. Build-linked findings identify the build, deliverable, owner and record reference.

  1. Select the relevant IATF 16949 or ISO/IEC 17025 framework view.
  2. Review Internal audit section overview. Each row states the assessment, score and objective LabOS evidence used.
  3. Review the Relevant norm map. A Manual review row means no automated evidence rule is mapped; it is deliberately not shown as compliant.
  4. Prioritise Major findings, then Minor findings. Recommendations / opportunities for improvement are preventive and are not nonconformities.
  5. Use the Prototype build turtle to review inputs, resources, people, controls, outputs and measures around the app process flow.
  6. Choose Audit evidence pack → Print / save PDF for the printable evidence set.

The readiness percentage is a system-assisted internal indicator, not a certification score. Ready = 100%, Minor = 50%, Major = 0% at check level; risk weights are used for the overall readiness calculation. Unmapped norm sections remain manual review items.

Task replan history

Prototype → [build] → Resource plan & committed timing → Task replan history.

Each row shows the movement, task, From → To date, reason category and retained free-text rationale. This is separate from customer commitment history.

Resource Assurance

Resource Assurance in the left navigation.

Use Calibration, Maintenance and Training filters to locate the exact resource. Schedule upcoming readiness work and retain the certificate/service/qualification evidence. A valid calibration interval should not trigger unnecessary recalibration; missing approval/evidence should guide to the evidence record instead.

Reports

Open Reports or the build closeout step. Build Reports and the Audit Evidence Pack use the browser print dialog; choose Save as PDF when a portable copy is required.

Prototype route/method hand-off

Prototype → open build → Build Workflow → Reuse released route / work instructions

  1. If a method is incomplete, the fixed Next Step action names that exact operation and opens the correct correction path.
  2. Operations such as Surface Preparation that are intentionally manual/no-dedicated-equipment are not blocked for lacking a machine.
  3. If the current user is the Lab Planner, choose Switch to Process Engineer · …. The same build remains open and the exact Process Engineering action is shown immediately.
  4. After route/method confirmation, the workflow proceeds forward to Controls and then Planning; it should not bounce back unless the controlled definition actually changes.
  5. If a reused route/work instruction has a genuine build-specific delta, the fixed NEXT ACTION names the exact remaining reviewer (Process Engineer, then Quality/Product Safety where configured). Complete that named sign-off; LabOS does not hand the build to the Planner until the definition/control stage is actually complete. Orphaned stale approval records are reconciled automatically.

Laboratory scope & resource evidence

Lab Standards & Resources → Equipment & laboratory scope

The scope register lists every registered equipment asset and links capability/range/resolution with current readiness, calibration certificate/validity, maintenance due/history and the certified skills/people associated with released methods using that capability.

Build Report capability plots

Reports → open Build Report → SC / CC & classified characteristics

Capability/statistical detail is expanded by default. Numeric special/critical characteristics show the measured distribution, specification/target/mean markers, Cpk context where supported by the data, normality result, anomalies and coverage.
